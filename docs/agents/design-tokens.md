# Design Tokens

The admin UI's visual vocabulary lives in `src/scss/tokens.scss` as CSS custom properties under the `--scb-` prefix, defined on `:root` and overridden under `.theme--dark`. They were read off the three surfaces that set the current look — the booking page, the booking editor and the bookable editor — and are what those pages and the shared `section-card.scss` / `booking-page.scss` now use.

## Rules

-   **Use a token, not a literal.** A colour, radius, hairline, font size or spacing step on a page or component surface reads `var(--scb-…)`. A new literal on one of the three pages is a review finding.
-   **One rule per property, both themes.** A token carries its dark value itself, so a component writes `color: var(--scb-text-muted)` once and no `.theme--dark` twin. Add a dark override only for something the tokens do not describe.
-   **Theme colours stay Vuetify's.** `--v-primary-base`, `--v-warning-base` and the rest come from `src/plugins/vuetify.js` (and the `VUE_APP_*_COLOR` env vars). The tokens only add the tints laid over them.
-   **Tints over the theme colour go through `color-mix()`.** `rgba(var(--v-primary-base), .08)` is not valid CSS — the custom property is a hex — and the browser drops it. Use `--scb-selected-tint` (8 %), `--scb-selected-tint-strong` (12 %) or `--scb-selected-tint-faint` (5 %).
-   **Breakpoints are Sass variables**, `$scb-bp-xs` (599px), `$scb-bp-sm` (959px), `$scb-bp-md` (1264px), because a media query cannot read a custom property. A plain scoped `<style>` writes the pixel value and names the variable in a comment beside it; a `lang="scss"` block can `@use "@/scss/tokens"`.
-   **Extend, do not fork.** A new role gets a token in `tokens.scss` with a comment naming where it is used. Do not define page-local `--booking-*`-style properties any more; the media library's `--media-surface-radius` is the one remaining local alias and equals `--scb-radius-surface`.

## Where the tokens are consumed

-   `src/scss/section-card.scss` — the section card and its header strip (every sectioned editor and the booking pages)
-   `src/scss/card.scss` — the interactive card `scb-card` (`--selected`, `--static`): bookable cards and the tenant cards of „Meine Mandanten“
-   `src/scss/toolbar.scss` — the search band `scb-search` that `SearchBar` draws on every list, the filter menu `scb-filter-menu`, and the row beneath the band `scb-toolbar` with `ToolbarRow`'s `scb-toolbar-row` (views, sorting, further actions). A new search uses `SearchBar`, not a `v-text-field` of its own
-   `src/scss/booking-page.scss` — captions, facts and rows of the booking pages; the booking editor's `BaseSection`
-   `src/views/BookingPage.vue`, `src/components/Booking/BookingEdit.vue`, `BookingEditSummary.vue`
-   `src/components/Bookable/BookableEdit.vue` (section nav, overview column, id chip) and `src/components/Bookable/Edit/*.vue`

Other surfaces (media library, dashboard, dialogs) still carry literals. Move them onto the tokens when a task touches them; do not sweep them in a drive-by.
